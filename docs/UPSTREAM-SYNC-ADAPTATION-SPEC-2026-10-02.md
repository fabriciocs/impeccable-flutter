### Decisão de sincronização

Não fazer reset, force-update ou substituição de `main` pelo upstream. A sincronização deve ser um merge/adaptação que preserve os 147 commits próprios do fork. O PR #12 é somente a âncora do upstream; ele não deve ser mergeado enquanto estiver conflitado.

## 2. Invariantes não negociáveis

1. Preservar suporte Flutter/Dart do fork, incluindo `crates/common/src/flutter.rs`, detector Dart/Flutter, referências Flutter e testes.
2. Node/npm permanece o toolchain JavaScript operacional. `package-lock.json` é canônico; `npm ci` deve funcionar em checkout limpo.
3. Não reintroduzir Playwright. Browser automation deve usar `puppeteer-core`, CDP direto ou o adapter `tests/lib/browser-driver.mjs`.
4. Não reintroduzir Bun como requisito de build/test/release. Funcionalidades upstream que usam `Bun.build`, `bun run`, `bunx`, `bun.lock` ou `.bun-version` devem ser portadas.
5. Não enfraquecer gates Rust, oracle, extension/WASM, generated-output, live E2E, Windows ou release.
6. Outputs de providers são derivados; editar fontes canônicas e regenerar.
7. No Windows, validação usa target Cargo isolado por execução e evidências por gate; lock de `target/release/impeccable.exe` compartilhado não pode decidir o resultado.
8. Nenhum arquivo do delta final pode ficar sem decisão documentada.

## 6. Regras específicas de portabilidade upstream

### 6.1 Component Review
O upstream introduz `ui/component-review/**`, testes associados e `scripts/build-component-review.mjs`. O fork deve incorporar a feature, mas substituir `Bun.build` por um bundler Node reproduzível. Recomendação: adicionar `esbuild` como devDependency pinada, gerar IIFE browser com `write:false` e gravar `crates/context/assets/component-review.js` via `node:fs`. O arquivo gerado precisa ser coberto por teste de determinismo/drift.

### 6.2 Browser automation
Todo teste upstream que importa Playwright, usa `needsPlaywright`, menciona cache `ms-playwright` ou exige `playwright install chromium` deve ser portado para `tests/lib/browser-driver.mjs`. Expandir o adapter uma vez para APIs faltantes; não criar wrappers diferentes por suite. O browser executável é resolvido por `scripts/lib/browser-executable.mjs` e pode ser Chrome, Chromium ou Edge.

### 6.3 Bun → Node/npm
Novos scripts upstream devem ser traduzidos para `node`, `npm run` ou binários locais. A CI não instala Bun. `bun.lock` continua removido; `package-lock.json` continua canônico. Qualquer código dependente do global `Bun` deve ser reescrito antes do merge.

### 6.4 Flutter
Mudanças upstream em `common`, `context`, `detect`, CLI, platform ou skill não podem reverter o modelo do fork. `framework/technology=flutter` permanece ortogonal a `platform`; Flutter Android/iOS/adaptive continua sujeito a source scan Dart; Flutter Web pode somar browser scan quando houver URL real.
